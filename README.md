## Thoughts
- 484 lines is a bit much some functions aren't as clean as I would like them to be 
- To be fair I was trying to do best practise with having the class declaration and definition in their respective files 
- twoAdjacentTiles() is a bit messy. 
- there were a lot of classes and functions that I didn't put in my original planning document. The more I do this the better I get at knowing what I need to build. Having a super clear plan at the start will save a lot of time in the long run and code will be clearer.
- pretty cool that I implemented the singleton design pattern. You just need a getInstance() function which initialises a static version of the object and returns a reference to it. Whenever getInstance() is called again it skips initialisation as the object already exists
- translations between enums and strings was a bit clumsy and over the top 
- maybe define more types to increase readability
